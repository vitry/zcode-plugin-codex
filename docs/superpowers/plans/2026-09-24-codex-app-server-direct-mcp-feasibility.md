# Codex App-server Direct MCP Feasibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce redacted real-host evidence and a four-gate decision on whether `mcpServer/tool/call` could support the existing foreground workflow through a deterministic plugin entry.

**Architecture:** Extend the disposable probe with a pre-validation handler-entry observer and a separate direct-call driver/reducer. Run state and lifecycle controls against one owned app-server connection; assess installed plugin entry independently. Preserve the original 0.155.1 qualification records and shell adapter.

**Tech Stack:** Node.js ≥22.13, ESM, `node:test`, `@modelcontextprotocol/sdk` 1.30.0, Codex app-server JSON-RPC, existing private JSONL observer and disposable marketplace fixture.

| `qualification/direct-mcp-feasibility.json` | Closed versioned decisions and evidence references only, with no raw identity. |

The implementation may place small private helpers beside these files, but each helper needs one responsibility and must be named in the task that introduces it. `tools/mcp-context-probe/` may receive a narrowly extracted reusable primitive; first run its 98-test baseline and keep its old records byte-identical.

The Task 2 event contract is fixed before real collection. Every row also carries `version`, `runNonce`, `sequence`, `kind`, and `phase`. `probeLabel` is a fresh random diagnostic label unique inside the run; `callNonce` is generated by the handler and first appears in `handler-entered`. Null is permitted only for a field explicitly described as optional below. Exact allowed values for `outcome`, `state`, and `source` are defined as closed enums in Task 2 and unit-tested before any Host run. Pre-collection amendment (2026-09-24, Task 2 gate review): `metadata-observed` additionally requires the closed boolean `fieldsTruncated`, so a capped field fingerprint is distinguishable from a short one; its `fields` entries record only allowlisted metadata paths plus a closed `[redacted]` token and closed JSON type names. No other kind changed. Pre-collection amendment (2026-09-24, Task 2 gate re-review rounds 6–7): every handler-side kind (`server-started`, `handler-entered`, `metadata-observed`, `hold-started`, `handler-settled`, `worker-settled`) additionally requires the closed `recordMac` — an HMAC-SHA256 over the canonical record (sequence included) keyed by the run capability secret the spawned server holds in memory — making handler provenance per-record authenticated and tamper-evident; driver-side kinds carry no `recordMac`.

| Kind | Additional permitted fields | Required fact |
| --- | --- | --- |
| `request-sent` | `probeLabel`, `tool`, `state` | Driver dispatched on its owned connection. |
| `server-started` | `serverInstanceHash`, `recordMac` | Disposable server initialized; not handler entry. |
| `readiness-observed` | `state`, `source` | Tool/server discovery or failure for the target thread. |
| `turn-state-observed` | `threadHash`, `turnHash`, `state`, `source` | Host-issued turn state before or after dispatch. |
| `handler-entered` | `probeLabel`, `callNonce`, `serverInstanceHash`, `recordMac` | Handler first action completed durable append. |
| `metadata-observed` | `callNonce`, `fields`, `fieldsTruncated`, `candidateHashes`, `state`, `recordMac` | Presence/types and salted candidates only; `state` reports missing/malformed/complete. |
| `hold-started` | `callNonce`, `workerHash`, `recordMac` | Held handler and synthetic worker started. |
| `trigger-sent` | `callNonce`, `outcome` | Driver sent an interrupt/close/timeout/completion trigger. |
| `trigger-observed` | `callNonce`, `outcome`, `source` | Host/transport acknowledged or rejected it. |
| `handler-settled` | `callNonce`, `outcome`, `recordMac` | Handler durable terminal. |
| `worker-settled` | `callNonce`, `workerHash`, `outcome`, `recordMac` | Synthetic worker durable terminal; may differ from handler. |
| `rpc-observed` | `probeLabel`, `callNonce` (optional until entry), `outcome` | RPC response or request failure. |
| `entry-action-observed` | `probeLabel`, `outcome`, `source` | Installed entry's explicit user action or missing route. |
| `terminal-delivered` | `probeLabel`, `outcome`, `source` | Original user/Child received the terminal result. |
| `cleanup-observed` | `outcome`, `source` | Probe-owned resources released, or exact redacted failure class. |

`threadHash`/`turnHash` must be derived from Host-issued IDs, never user text. `candidateHashes` is a bounded map from allowlisted metadata field paths to hashes or absence, not an open JSON object. `workerHash` identifies a probe-owned synthetic worker, not a real job. The reducer rejects fields not listed for their kind and refuses to interpret a driver record as proof of handler or worker settlement.

## Task 2: Prove handler entry independently of metadata

**Files:** Create `tools/direct-mcp-probe/observer.mjs`; create `tools/direct-mcp-probe/server.mjs`; modify `tests/direct-mcp-probe.test.mjs`.

- [ ] **Step 1: Define closed evidence and decision formats before any live collection.** Each event uses `{version:1, runNonce, sequence, kind}` and a kind-specific allowlist. The complete event-kind union is `request-sent`, `server-started`, `readiness-observed`, `turn-state-observed`, `handler-entered`, `metadata-observed`, `hold-started`, `trigger-sent`, `trigger-observed`, `handler-settled`, `worker-settled`, `rpc-observed`, `entry-action-observed`, `terminal-delivered`, and `cleanup-observed`. Call-scoped events additionally require `callNonce`; request and handler use the same opaque `probeLabel` for diagnostic correlation, while the handler creates `callNonce` and writes it with `probeLabel` at entry. A driver event refers to that `callNonce` only after a durable join on one unique `probeLabel` in the run and bounded phase; ambiguity fails closed. Neither value grants authority. Kind-specific fields are closed enums, booleans, bounded counters, field-name/type pairs, and salted hashes; no generic spread, arbitrary payload, raw ID, or raw path. Define every kind's allowed and required keys before the first live run; later tasks may select outcomes from the predefined enum but not silently add kinds. The separate result record uses `version:1`, exact Host/source provenance, evidence digest/count, and keys `G1`–`G4`; each gate has `{status:'proven'|'not-proven'|'incompatible-under-tested-conditions', reasonCode, evidenceRefs}`. `handler-entered` allows absent metadata; unknown fields and wrong run nonce fail. The reducer checks unique labels, exact call nonce, event order, and per-phase prerequisites. Add negative tests for missing entry, duplicate entry, duplicate label, wrong nonce, reversed order, truncated final JSONL, symlinked evidence, and an error response with no entry (origin stays `unknown`).

## Task 4: Characterize active turn and authority without assuming a metadata field

## Decision at completion
