# Map current Codex permissions to headless ZCode requests

Review runs deny every ZCode operation request that can mutate state. Writable Rescue runs allow low- and medium-risk requests, while high-risk requests are allowed only when the current Codex turn is explicitly in `bypassPermissions`; an absent or uncertain mode denies high risk. A Codex `UserPromptSubmit` hook records the documented `session_id`, `turn_id`, and `permission_mode` in a private exact-session/workspace active-turn record. As revised by ADR 0010, the companion resolves that record using the runtime-observed `CODEX_THREAD_ID` plus the canonical workspace and fails closed on any mismatch; no capability is passed through the model. Job reservation copies the record into an immutable permission snapshot before ZCode starts. Production-owned background children use the parent job's snapshot rather than their own later hook state. Only the exact `bypassPermissions` value grants high-risk permission because ZCode has no OS sandbox behind its protocol-level permission request. Workspace-wide latest-session markers remain forbidden.
