# Map current Codex permissions to headless ZCode requests

Review runs deny every ZCode operation request that can mutate state. Writable Rescue runs allow low- and medium-risk requests, while high-risk requests are allowed only when the current Codex turn is explicitly in `bypassPermissions`; an absent or uncertain mode denies high risk. A Codex `UserPromptSubmit` hook records the documented `session_id`, `turn_id`, and `permission_mode` behind a random opaque caller-context capability, and the Skill passes that internal capability to the companion. Job reservation validates it and copies the record into an immutable permission snapshot before ZCode starts. Background forwarding children use the parent job's snapshot rather than their own later hook state. Only the exact `bypassPermissions` value grants high-risk permission because ZCode has no OS sandbox behind its protocol-level permission request. Workspace-wide latest-session markers and undocumented thread environment variables are not identity sources.
