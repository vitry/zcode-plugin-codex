# Bind a stopped Rescue child to its exact ZCode session

## Decision

Root may send the constant `invoke-prepared rescue` assignment to the same stopped child after privately preparing a new turn. The durable binding keeps the original `anchorJobId` and advances `currentJobId` when the continuation job is durably reserved and published. If it queues and fails as the exact active-version-3 pre-running case below, rollback restores the prior binding. Otherwise the advancement remains authoritative after acceptance, running state, a task boundary, or the existing cancellation lifecycle. Those identifiers, the task, permissions, workspace identity, and executor provenance remain private plugin state and never enter a child assignment.

An active exact child is rejoined without preparation or invocation. A stopped exact same-operation child is re-authorized by the new prepared turn and followed up without another spawn or `SubagentStart`. A fresh or independent operation prepares `fresh` and creates a new child. Root alone decides these semantics; the child only executes its fixed assignment once per child turn.

### Pre-running continuation failure

Reservation-time publication advances `currentJobId` before the resumed ZCode turn begins. This ordering is required: concurrent callers must see the newly reserved continuation instead of both reserving from the same anchor. If that active version-3 continuation fails before running state or any task boundary is persisted, one workspace-locked transaction must restore the exact saved prior binding and retain the new attempt as a failed job. It must not create a fresh session, choose another binding, or hide the failed attempt.

The rollback is a compare-and-swap operation over the complete continuation proof. The active binding must still point to that exact queued job, and the binding key, operation, parent, child identity/path, workspace, permission, anchor, generation, and saved prior binding must all remain unchanged. An unclaimed attempt requires the exact absence of a worker lease; a claimed lease identifier participates in the same compare-and-swap fence. Any running timestamp, accepted ZCode session, input or revision, task boundary, result, changed lease, or competing binding update makes rollback ineligible and fails closed.

Binding restoration publishes before the retained failed job, which defines crash convergence: a retry accepts only the two proved states—an exact advanced binding plus its queued proof, or the exact restored binding plus that same attempt already terminalized. The restored binding receives a strictly monotonic `updatedAt`. Terminal publication immediately removes the continuation origin, execution claim, and job-spec commitment. The execution reservation remains until the existing identity cleanup releases and clears it, while worker-fence metadata follows the terminal job schema. A settlement failure never silently replaces the execution failure: both remain available through the explicit settlement error, and a durable terminal winner is authoritative when reread proves it.

Runtime correction and operator-only maintenance remain separate. The runtime correction applies only to ordinary active version-3 continuations before running state. The existing legacy v1/v2 `closed/session-ended` migration boundary and its rollback remain unchanged. Historical damage is handled separately by the maintenance CLI: it requires exact incident identities and expected binding generation, defaults to a non-mutating inspection, performs the same locked fail-closed validation, preserves the failed job, and is excluded from package and marketplace payloads. Runtime correction never scans for repair candidates or invokes this maintenance path automatically.

## Compatibility and lifecycle

Legacy jobs-only state may be adopted only when it supplies one exact eligible candidate and no conflicting pending state. A permission change prevents resume and requires an explicit fresh operation to capture the current permission snapshot. `SessionEnd` means runtime ownership loss: it may settle writable jobs and clean runtime resources, but preserves exact durable bindings for a later Root resume. Missing, invalid, revoked, corrupt, ambiguous, wrong-workspace, wrong-executor, or provenance-mismatched state must fail closed without selecting a latest session or another child.

The lifecycle distinguishes resident, unloaded but resumable, completed but resumable, and revoked. Mapping is exact child-scoped by parent session, canonical workspace, child identity/path/Role, and binding operation. A fresh operation on a different child does not close the first child's binding; only an explicit same-child replacement may supersede that child. Contradictory or ambiguous mappings fail closed. `WRITABLE_JOB_EXISTS` remains a separate conservative writable-exclusion policy: one canonical workspace admits at most one active writable Rescue. Relaxing that policy could materially improve parallel Rescue throughput, but it requires a separate isolation and admission design to prevent concurrent writers from corrupting shared workspace state; this continuation fix neither authorizes nor implements that change.

Root retains the exact canonical `task_name` returned by its successful spawn as that logical operation's path; Root neither receives nor supplies the host child ID. For an exact continuation it may place only that path in a private version-3 `{agentPath}` selector. Multiple otherwise valid sibling bindings are then not an authorization ambiguity by themselves: after validating the complete exact-parent child graph and rejecting duplicate IDs or paths, the plugin requires the path to match exactly one host child and obtains that host record's child ID internally. The selected host must still pass the complete Role, path, workspace, permission, executor, durable child-ID/path binding, operation, generation, job, and original ZCode-session join. The canonical path selects but grants no authority and cannot hide malformed or duplicate host metadata. An absent or null continuation target remains valid only under the existing targetless rule: one uniquely eligible complete binding must exist. For a supplied non-null selector, a missing or malformed `agentPath`, failure to exactly resolve one host child, or failure of the exact binding join must fail closed without sibling substitution or fresh fallback. Without an exact selector, multiple usable bindings remain ambiguous. Private envelope version 2's exact `{childId, agentPath}` form remains read compatibility only for already-created preparations; new flows emit version 3.

For linked worktrees, the prompt-proved origin workspace and the Rescue execution workspace are distinct. The first trusted prepare automatically binds one immutable execution target for the turn, without manual handoff, and only an exact canonical linked worktree sharing the same canonical Git common-dir is eligible. A child cannot claim the target. The stopped child's generation-bound route and all durable binding state remain in that execution workspace; Root Stop and a new prompt revoke or replace the origin authority before cleaning the target, while SessionEnd only removes runtime ownership and preserves exact resumable bindings.

This replaces ADR 0010 only where that decision treated a stopped child as reusable solely for the immediate `needs-choice` exchange. Choice continuation remains same-child; this decision also permits a later prepared turn for the exact durably bound operation.
